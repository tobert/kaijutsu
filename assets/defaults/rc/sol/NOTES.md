# Sol stance notes

The gpt-6.2-sol Codex base instructions emphasize finishing authorized work,
checking each deliverable, and recovering from failed attempts. We pair that
with coder's test or rubric at the start, a sample before further inspection,
and explicit guesses. We kept brief updates, a final report that stands on its
own, and edits that preserve caller behavior and the author's wording. The
review rule adds a local convention: lead with findings a reader can verify.
The base instructions discuss reviewing existing content but give no code review
format.

We kept coder's lifecycle scripts and links. S36 supplies project rules. The
stance uses kaish for search and long work and `done` to end the task. We left
out Codex tool names, approval and sandbox mechanics, skills and plugin rules,
frontend and rendering guidance, and branding. We kept our testing practice
and writing rules in place of Codex's test default and punctuation rules.

The model metadata sets low default verbosity in Codex. We used that as a cue
for brief reports and left tool mode and truncation to the runtime. We do not
know how much of the guidance is specific to Sol or how it will affect long
tasks here. Revisit after observing several Sol contexts.
